| Boundary | Description |
|----------|-------------|
| Scenario fixtures -> dataset cases | Shared fixture state must be referenced correctly so cases do not drift or point at nonexistent corpus setups |
| Dataset cases -> future endpoint runner | Expectations must describe live v1/v2 contracts precisely enough that later execution does not reinterpret them |
| Maintainer-authored labels -> governance assertions | Human-authored relevance labels cannot be allowed to mask forbidden-result leakage |

| T-25-06 | I | retrieval dataset expectations | mitigate | Require explicit `governance.forbiddenIds` and endpoint-specific shape assertions in positive, empty, and forbidden cases so governance leakage remains independently visible from relevance labels. |

| T-25-08 | E | dataset fixture state | accept | Phase 25 datasets only describe expected authorization/governance behavior; real permission enforcement stays in server code and Phase 26 execution adapters, so no new privilege boundary is introduced here. |
