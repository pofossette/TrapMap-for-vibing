# Plan 33-06: Startup Recovery for In-Flight Candidates

## Goal
Implement server startup recovery to reprocess candidates that were interrupted during processing (server crash, restart, etc.).

## Context
When the server restarts, candidates in 'queued' or 'analyzing' state need to be recovered and reprocessed. This ensures no candidates are lost due to server interruptions.

## Tasks

### Task 1: Add startup recovery hook in app initialization

<read_first>
- packages/server/src/app.ts (full file)
- packages/server/src/lib/candidates/processor.ts (for processPendingCandidates)
- packages/server/src/lib/candidates/store.ts (for resetInterruptedCandidates)
</read_first>

<action>
Modify `packages/server/src/app.ts` to:

1. Import recovery functions:
```typescript
import {
  processPendingCandidates,
  resetInterruptedCandidates,
  findInterruptedCandidates,
} from './lib/candidates/index.js';
```

2. Add recovery logic after store initialization (find where the app is ready, often after `app.ready()` or similar):

Add a function to run on server ready:
```typescript
// Recovery: Reprocess interrupted candidates on startup
app.addHook('onReady', async () => {
  try {
    const data = await app.skillShareer.store.snapshot();
    const interrupted = findInterruptedCandidates(data);

    if (interrupted.length > 0) {
      app.log.info(
        { count: interrupted.length },
        'Found interrupted candidates, scheduling recovery',
      );

      // Reset them to 'received' status
      await app.skillShareer.store.transact((txData) => {
        resetInterruptedCandidates({
          data: txData,
          reason: 'Server restart recovery',
        });
      });

      // Fire-and-forget processing
      void processPendingCandidates({
        store: app.skillShareer.store,
        getSnapshot: () => app.skillShareer.store.snapshot(),
      }).then(({ processed, errors }) => {
        app.log.info(
          { processed, errors },
          'Candidate recovery complete',
        );
      }).catch((error) => {
        app.log.error({ error }, 'Candidate recovery failed');
      });
    }
  } catch (error) {
    app.log.error({ error }, 'Failed to check for interrupted candidates');
  }
});
```

If Fastify's `onReady` hook is not suitable, use an equivalent pattern like:
- After `await app.ready()` in the main app function
- In the server start logic after listening

The key is that this runs once when the server starts and before accepting requests.
</action>
