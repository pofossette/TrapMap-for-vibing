# 27-02: Implement Summary Evaluation Command and Reports with Groundedness-Oriented Scoring

## Requirements

- SEVAL-01: Maintainer can run summary/refinement evaluation flow that scores groundedness, coverage, and citation adherence
- SEVAL-02: Summary evaluation uses milestone-owned evaluation cases with required facts and forbidden claims so hallucinations are visible in reports

## Goal

Implement the summary evaluation runner with LLM-as-judge integration for claims extraction and groundedness verification. Build the report generator that distinguishes unsupported claims from grounded summaries.

## Tasks

### Task 27-02-02: Implement fallback (rules-based) judge

<read_first>

</read_first>

<action>

1. Export `JudgeConfig` interface:
```typescript
export interface JudgeConfig {
  provider: JudgeProvider;
  model?: string; // e.g., 'gpt-4o-mini' for OpenAI
  temperature?: number; // default 0 for determinism
}
```

2. Export `fallbackVerifyClaims(params: { claims: ExtractedClaim[]; context: string[]; }): ClaimVerification[]`:
   - For each claim, check if simplified claim text appears in any context item
   - Use substring matching on simplified forms
   - Return ClaimVerification with supported=true if match found, false otherwise
   - Include matched context as evidence

3. Export `fallbackCheckForbidden(params: { summaryText: string; forbiddenClaims: string[]; }): string[]`:
   - For each forbidden claim pattern, check if it appears in summary (case-insensitive)
   - Return array of forbidden claims that were found

4. Export `fallbackJudge(params: { summaryText: string; context: string[]; requiredFacts: string[]; forbiddenClaims: string[]; }): SummaryJudgeResult`:
   - Extract claims from summaryText
   - Verify each claim against context using fallbackVerifyClaims
   - Calculate groundednessScore = supportedClaims / totalClaims
   - Check required facts coverage: requiredFactsCovered = facts found in summary
   - Check forbidden claims using fallbackCheckForbidden
   - Calculate coverageScore = requiredFactsCovered.length / requiredFacts.length
   - Return complete SummaryJudgeResult with provider: 'fallback'

5. Export `createJudge(config: JudgeConfig)` function that returns:
   - For now, only fallback judge is implemented
   - OpenAI integration placeholder with comment for future implementation
   - Return object with `evaluate(summaryText, context, expected)` method
</action>
