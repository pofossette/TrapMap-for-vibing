# Part A: Type Deduplication — Canonicalize AdapterSyncState and KnowledgeIndexStateRecord

## Objective

Eliminate duplicate type definitions by establishing `indexing/types.ts` as the canonical location for `AdapterSyncState` and `KnowledgeIndexStateRecord`. Remove duplicate definitions from `store.ts` and add an import.

## Context

Both files define identical interfaces:
- `AdapterSyncState`: sync status for index adapters (status, revision, contentHash, lastSyncedAt, lastError)
- `KnowledgeIndexStateRecord`: complete index state on KnowledgeRecord (contentHash, normalizedAt, vector, keyword, graph)

`indexing/types.ts` is the canonical home because:
1. It defines the full indexing type vocabulary (`NormalizedIndexDocument`, `IndexAdapter`, `IndexSyncResult`, `KeywordAdapterSyncState`)
2. `store.ts` already imports from other modules (`@trapmap/contracts`, `./indexing/graph-lite/documents.js`)
3. Reduces the type surface of `store.ts` (~800 lines)
