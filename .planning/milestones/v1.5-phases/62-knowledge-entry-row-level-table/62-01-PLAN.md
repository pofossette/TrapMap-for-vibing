# Phase 62-01: Schema Definition and Repository Interface

## Objective

Define the PostgreSQL table schemas for `knowledge_entries`, `knowledge_revisions`, and `lifecycle_events`, and create the `KnowledgeRepository` interface that abstracts knowledge entry persistence operations.

## Context

Phase 61 established the pattern for extracting data from the JSONB snapshot into row-level PostgreSQL tables. This phase applies the same pattern to knowledge entries, which are more complex due to:
- Multiple related tables (entries, revisions, lifecycle events)
- Rich domain model with governance metadata
- Existing embedding/keyword index tables that reference entry_id

**Note:** The existing `packages/server/src/lib/knowledge.ts` is a single file. This phase creates a new `packages/server/src/lib/knowledge/` directory structure. Task 3 migrates relevant exports from `knowledge.ts` into the new directory structure.

<threat_model>
## Threat Model

| Threat | STRIDE | Mitigation |
|--------|--------|------------|
| SQL injection via knowledge fields | Tampering | Parameterized queries via pg driver (no string concatenation in SQL) |
| Race condition on lifecycle transitions | Tampering | Row-level SELECT FOR UPDATE on individual entry rows |
| Data divergence between relational and JSONB | Tampering | Dual-write with primary-first ordering; reconciliation in migration script |
</threat_model>

## Tasks

### Task 1: Add Table Schemas and SEQUENCE to schema.ts

<read_first>
- packages/server/src/lib/persistence/schema.ts (existing candidates table pattern)
- packages/server/src/lib/store.ts (KnowledgeRecord, KnowledgeRevisionRecord, KnowledgeLifecycleEventRecord types)
- packages/contracts/src/domain/knowledge.ts (KnowledgeEntry type definition)
</read_first>

**Implementation:**

1. Add `knowledge_entry_id_seq` SEQUENCE for ID generation:
   ```sql
   CREATE SEQUENCE IF NOT EXISTS knowledge_entry_id_seq START 1;
   ```

2. Add `knowledge_entries` table definition after `candidates` table:
   - id (TEXT PRIMARY KEY) - generated via `nextval('knowledge_entry_id_seq')::text`
   - team_id (TEXT, nullable)
   - scope (TEXT NOT NULL)
   - labels (JSONB NOT NULL, string array)
   - shortcut (TEXT NOT NULL)
   - detail (TEXT NOT NULL)
   - required_level (INTEGER NOT NULL DEFAULT 0)
   - lifecycle_state (TEXT NOT NULL)
   - owner_user_id (TEXT NOT NULL)
   - boundary (JSONB, nullable)
   - maintenance_meta (JSONB, nullable)
   - created_at (TIMESTAMP WITH TIME ZONE NOT NULL)
   - updated_at (TIMESTAMP WITH TIME ZONE NOT NULL)

3. Add `knowledge_revisions` table definition:
   - id (TEXT PRIMARY KEY) - composite: `{entry_id}_rev{revision}`
   - entry_id (TEXT NOT NULL)
   - revision (INTEGER NOT NULL)
   - submitted_at (TIMESTAMP WITH TIME ZONE NOT NULL)
   - submitted_by_user_id (TEXT NOT NULL)
   - shortcut (TEXT NOT NULL)
   - detail (TEXT NOT NULL)
   - labels (JSONB NOT NULL)
   - review_notes (JSONB NOT NULL)
   - created_at (TIMESTAMP WITH TIME ZONE NOT NULL)

4. Add `lifecycle_events` table definition:
   - id (TEXT PRIMARY KEY)
   - entry_id (TEXT NOT NULL)
   - type (TEXT NOT NULL)
   - created_at (TIMESTAMP WITH TIME ZONE NOT NULL)
   - actor_user_id (TEXT, nullable)
   - submission_id (TEXT, nullable)
   - revision (INTEGER, nullable)
   - state (TEXT NOT NULL) - stores LifecycleState string values ('submitted', 'agent-pass', 'approved', etc.)
   - note (TEXT, nullable)

5. Create indexes:
   - `idx_knowledge_entries_lifecycle_state ON knowledge_entries(lifecycle_state)`
   - `idx_knowledge_entries_team ON knowledge_entries(team_id) WHERE team_id IS NOT NULL`
   - `idx_knowledge_revisions_entry ON knowledge_revisions(entry_id)`
   - `idx_lifecycle_events_entry ON lifecycle_events(entry_id)`

### Task 2: Create KnowledgeRepository Interface

<read_first>
- packages/server/src/lib/candidates/repository.ts (CandidateRepository interface pattern)
- packages/server/src/lib/store.ts (KnowledgeRecord type)
- packages/server/src/lib/knowledge.ts (createKnowledgeEntryRecord, updateKnowledgeEntry functions)
</read_first>

**Implementation:**

Create `packages/server/src/lib/knowledge/repository.ts` with:

1. Define `KnowledgeRepository` interface with methods:
   - `insert(entry: KnowledgeRecord): Promise<void>`
   - `getById(entryId: string): Promise<KnowledgeRecord | null>`
   - `updateLifecycle(entryId: string, newState: LifecycleState, context: { actorId: string; note?: string }): Promise<void>`
   - `appendRevision(entryId: string, revision: KnowledgeRevisionRecord): Promise<void>`
   - `appendLifecycleEvent(entryId: string, event: KnowledgeLifecycleEventRecord): Promise<void>`
   - `listByFilter(filter: { lifecycleState?: LifecycleState; teamId?: string; ownerUserId?: string }): Promise<KnowledgeRecord[]>`
   - `updateGovernance(entryId: string, governance: { labels?: string[]; requiredLevel?: number }): Promise<void>`
   - `nextId(): Promise<string>` - uses PostgreSQL SEQUENCE (nextval)

2. Create `DualWriteKnowledgeRepository` class that implements the interface:
   - Writes to primary repository first (PostgreSQL)
   - Shadow-writes to JSONB via `store.transact()`
   - Follows the exact pattern from `DualWriteCandidateRepository`

3. Create `InMemoryKnowledgeRepository` class that uses `store.transact()` for all operations (for tests without PostgreSQL pool)

4. Create `createKnowledgeRepository(config: { pool?: Pool; store: SkillShareerStore }): KnowledgeRepository` factory function
