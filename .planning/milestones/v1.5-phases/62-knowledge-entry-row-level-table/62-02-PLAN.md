# Phase 62-02: PostgreSQL Knowledge Repository Implementation

## Objective

Implement `PgKnowledgeRepository` with row-level locking for concurrent-safe operations, and create comprehensive tests for all repository methods.

## Context

Wave 0 defined the schemas and interfaces. This wave implements the actual PostgreSQL-backed repository that performs CRUD operations on the new tables with proper transaction handling and row-level locking.

<threat_model>
## Threat Model

| Threat | STRIDE | Mitigation |
|--------|--------|------------|
| SQL injection via knowledge fields | Tampering | Parameterized queries via pg driver (no string concatenation in SQL) |
| Race condition on lifecycle transitions | Tampering | Row-level SELECT FOR UPDATE on individual entry rows |
| Concurrent revision number assignment | Tampering | SELECT MAX(revision) within same transaction as INSERT |
</threat_model>

### Task 1: Implement PgKnowledgeRepository

<read_first>
- packages/server/src/lib/candidates/pg-repository.ts (PgCandidateRepository pattern)

- packages/server/src/lib/knowledge/repository.ts (KnowledgeRepository interface)
- packages/server/src/lib/store.ts (KnowledgeRecord, KnowledgeRevisionRecord types)
</read_first>

**Implementation:**

Create `packages/server/src/lib/knowledge/pg-repository.ts`:

1. Class constructor takes `Pool` and creates Drizzle instance:
   ```typescript
   export class PgKnowledgeRepository implements KnowledgeRepository {
     private db: ReturnType<typeof drizzle>;
     private initialized = false;

     constructor(private readonly pool: Pool) {
       this.db = drizzle(pool, { schema: { knowledgeEntries, knowledgeRevisions, lifecycleEvents } });
     }
   }
   ```

2. Implement `ensureSchema()` method:
   - Create `knowledge_entry_id_seq` SEQUENCE if not exists
   - Create `knowledge_entries` table if not exists
   - Create `knowledge_revisions` table if not exists
   - Create `lifecycle_events` table if not exists
   - Create all indexes

3. Implement `nextId(): Promise<string>`:
   - Execute `SELECT nextval('knowledge_entry_id_seq')::text AS id`
   - Return the generated ID string
   - This replaces the in-memory counter pattern from `store.nextId(data, 'knowledge')`

4. Implement `insert(entry: KnowledgeRecord): Promise<void>`:
   - Use transaction with BEGIN/COMMIT
   - INSERT into knowledge_entries
   - INSERT all revisions into knowledge_revisions
   - INSERT all lifecycle events into lifecycle_events
   - Handle conflict on id (throw error if already exists)

5. Implement `getById(entryId: string): Promise<KnowledgeRecord | null>`:
   - Query knowledge_entries
   - Query knowledge_revisions WHERE entry_id = $1 ORDER BY revision
   - Query lifecycle_events WHERE entry_id = $1 ORDER BY created_at
   - Reconstruct full KnowledgeRecord from rows

6. Implement `updateLifecycle(entryId, newState, context)`:
   - Use `SELECT ... FOR UPDATE` for row-level locking
   - Validate transition using `transitionLifecycleState` from state-machine module
   - UPDATE knowledge_entries SET lifecycle_state = $1, updated_at = NOW()
   - INSERT new lifecycle_event record

7. Implement `appendRevision(entryId, revision)`:
   - Use `SELECT ... FOR UPDATE` to lock entry row
   - INSERT into knowledge_revisions
   - UPDATE knowledge_entries SET latest_revision columns

8. Implement `appendLifecycleEvent(entryId, event)`:
   - INSERT into lifecycle_events

9. Implement `listByFilter(filter)`:
   - Build dynamic WHERE clause from filter
   - Query knowledge_entries
   - Return lightweight records (no full revision history)

10. Implement `updateGovernance(entryId, governance)`:
    - Use `SELECT ... FOR UPDATE`
    - UPDATE knowledge_entries with new labels/requiredLevel
