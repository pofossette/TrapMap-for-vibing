<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| CLI caller -> server route | Untrusted edit payloads and artifact IDs enter the authenticated edit endpoint |
| Route -> edit helper | Authorized requests cross from HTTP/auth parsing into merge and revision logic |
| Server response -> CLI formatter | Only filtered metadata should reach human or JSON output |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-19-04 | S | `POST /v1/operations/artifacts/:artifactId/edit` | mitigate | Resolve auth from the saved session and require `knowledge:submit` before payload parsing. |
| T-19-05 | I | `packages/server/src/lib/artifacts/edit.ts` | mitigate | Apply same governance filters (team access, security level) as export to prevent cross-team edits. |
| T-19-06 | T | artifact merge logic | mitigate | Full file replacement ensures no orphaned files; source hash computation from derivation-eligible files ensures deterministic caching. |
| T-19-07 | E | edit permission check | mitigate | Owner OR strictly higher security level required; same-level non-owner cannot edit. |
| T-19-08 | R | audit trail for edits | accept | All edit operations create audit events for traceability; logging phases 21-22 will add operation-level logging. |
| T-19-09 | D | history view access | mitigate | Apply same governance filters as export to prevent unauthorized history disclosure. |
</threat_model>
