## Cross-Phase Integration Issues

### Dormant Optimization: Batch Embeddings (PERF-01)

- `getBatchEmbeddings()` and `optimizedSemanticRecall()` in `semantic.ts` are exported but never imported by the orchestrator
- The in-memory semantic recall path continues to use original line-by-line `Promise.all()` processing
- Orchestrator.ts line 563 uses `semanticGetEntryEmbedding()` instead of the batch path

### Dormant Optimization: Early Termination (PERF-01)

- `earlyTerminationThreshold` option in `rerank.ts` is defined and tested
- All 3 callers in `orchestrator.ts` (lines 689, 718, 819) omit this parameter
- Reranking processes all candidates without pre-filtering

### Missing Lifecycle: HNSW Index (PERF-02)

- `ensureVectorIndex()` in `db-search.ts` is never called at startup
- Phase 72 Plan 04 SUMMARY claimed "The HNSW index is created automatically during server startup"
- `vectorSimilaritySearch()` hardcodes `indexUsed: true` regardless of actual index state
- If index is not created externally, vector search degrades to sequential scan silently

### Orphaned Function: Memory Optimization (PERF-03)

- `reconcileKnowledgeIndexes()` in `pipeline.ts` has batch processing and memory logging
- Function is never called from production code — only `syncKnowledgeIndex` is used by `events.ts`
- Batch size (50), memory delta logging, and GC hints are dormant
