# Plan 70-01: Retrieval Merge and Semantic Unit Tests

**Goal:** Add pure unit tests for merge.ts and semantic.ts to cover multi-path merge strategy and semantic recall calculations.

## Scope

Create two test files:
1. `packages/server/src/lib/retrieval/merge.test.ts` - Multi-path merge strategy tests
2. `packages/server/src/lib/retrieval/recall/semantic.test.ts` - Semantic recall helper tests

These are pure function modules with no database or service dependencies, ideal for fast unit tests.

## Test File 1: merge.test.ts

### Test Categories

#### mergeCandidates()

1. **Basic merge behavior**
   - merges empty semantic and keyword candidates → returns empty array
   - merges semantic-only candidates → preserves with semantic weight
   - merges keyword-only candidates → preserves with keyword weight
   - merges both channels → combines scores with weighted average
   - deduplicates by entry.id when same entry in both channels

2. **Score calculation**
   - applies DEFAULT_SEMANTIC_WEIGHT (0.6) to semantic score
   - applies DEFAULT_KEYWORD_WEIGHT (0.4) to keyword score
   - combines scores correctly when entry in both channels
   - respects custom weights via MergeConfig

3. **Determinism and ordering**
   - sorts by combined score descending
   - uses entry.id as tiebreaker for stable ordering
   - produces identical results for identical inputs

4. **Channel tracking**
   - sets channels: ['semantic'] for semantic-only
   - sets channels: ['keyword'] for keyword-only
   - sets channels: ['semantic', 'keyword'] for merged

5. **Token match preservation**
   - preserves tokenMatches from keyword channel
   - sets empty tokenMatches for semantic-only

6. **maxCandidates limit**
   - respects maxCandidates config option
   - returns all candidates when maxCandidates not specified

#### toScoredEntry() and toScoredEntries()

- converts MergedCandidate to ScoredEntry with combinedScore
- batch conversion preserves order

#### createSemanticCandidate()

- creates RecallCandidate with channel: 'semantic'
- sets empty tokenMatches array

#### hasBothChannels()

- returns true when channels includes both semantic and keyword
- returns false when only one channel

### Test Count Estimate: 20-25 tests

## Test File 2: semantic.test.ts

### Test Categories

#### buildEmbeddingText()

- concatenates shortcut, detail, and labels
- trims whitespace
- handles empty labels array
- handles entries with all empty fields

#### cosineSimilarity()

- returns 1.0 for identical vectors
- returns 0.0 for orthogonal vectors
- returns correct value for known similar vectors
- returns 0.0 when either magnitude is 0
- throws error for mismatched dimensions
- handles negative values correctly

#### computeScore()

- clamps similarity to [0, 1] range
- applies 0.05 boost per matching label
- applies 0.03 boost for exact scope match
- caps score at 1.0 with boosts
- handles empty filters (no boost)
- handles multiple matching labels

#### getEntryEmbedding() and getQueryEmbedding()

Note: These call generateEmbedding which requires mocking.

- getQueryEmbedding calls generateEmbedding with query text
- getEntryEmbedding uses embeddingCache when valid
- getEntryEmbedding recomputes when cache is stale
- getEntryEmbedding prefers indexState.vector when synced

### Mocking Strategy

For semantic.test.ts, mock `../../embeddings.js`:
```typescript
vi.mock('../../embeddings.js', () => ({
  generateEmbedding: vi.fn().mockResolvedValue([0.1, 0.2, 0.3]),
  hashEmbeddingText: vi.fn().mockReturnValue('mock-hash'),

```

### Test Count Estimate: 15-20 tests
