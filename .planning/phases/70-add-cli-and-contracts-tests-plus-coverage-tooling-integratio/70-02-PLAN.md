# Plan 70-02: Retrieval Orchestrator Tests

**Goal:** Add unit tests for the retrieval orchestrator covering strategy selection, routing logic, and pipeline coordination.

## Scope

Create one test file:
- `packages/server/src/lib/retrieval/orchestrator.test.ts`

The orchestrator is complex with external dependencies. Focus on testable pure functions first, then add integration-style tests with mocks.

## Test Categories

### Part 1: selectRetrievalStrategy() - Pure Function Tests

These require no mocking - test the deterministic routing logic.

1. **Mode mapping (V1)**
   - 'semantic' → strategy 'local', channels ['semantic']
   - 'hybrid' → strategy 'hybrid', channels ['semantic', 'keyword']
   - 'graph-assisted' → strategy 'mix', channels ['semantic', 'keyword', 'graph']
   - unknown mode → defaults to 'local'

2. **RoutingDecision structure**
   - returns correct routeFamily: 'entry' for v1
   - sets routingReason: 'explicit-mode'
   - fallbackApplied is false for valid modes
   - channelsUsed starts empty (populated after recall)

### Part 2: selectRetrievalStrategyV2() - Pure Function Tests

1. **V2 defaults**
   - returns strategy 'local'
   - returns routeFamily: 'capsule'
   - returns routingReason: 'v2-default-capsule'
   - channelsPlanned: ['capsule', 'profile']

### Part 3: toRoutingTrace() - Pure Function Tests

- converts RetrievalDecision to trace format
- omits channelsPlanned from output

### Part 4: inferChannelsFromMerged() - Pure Function Tests

- returns ['semantic'] for undefined mergedCandidates
- returns ['semantic'] for empty mergedCandidates
- extracts unique channels from merged candidates
- returns all channel types present

### Part 5: searchKnowledge() - With Mocks

For the main search function, use extensive mocking:

```typescript
vi.mock('./recall/semantic.js', () => ({
  getQueryEmbedding: vi.fn().mockResolvedValue([0.1, 0.2, 0.3]),
  getEntryEmbedding: vi.fn().mockResolvedValue([0.1, 0.2, 0.3]),
  cosineSimilarity: vi.fn().mockReturnValue(0.8),
  computeScore: vi.fn().mockReturnValue(0.8),
}));

vi.mock('./recall/keyword.js', () => ({
  keywordRecall: vi.fn().mockResolvedValue([]),
  normalizeQuery: vi.fn().mockReturnValue(['test']),
}));

vi.mock('./recall/graph-assisted.js', () => ({
  graphAssistedRecall: vi.fn().mockResolvedValue([]),
}));
```

1. **Empty results path**
   - returns buildEmptyResponse() when no eligible entries
   - logs RAG retrieval with resultCount: 0

2. **Mode dispatch**
   - dispatches to semanticRecall for mode='semantic'
   - dispatches to hybridRecall for mode='hybrid'
   - dispatches to graphAssistedRecall for mode='graph-assisted'
   - throws AppError for invalid mode

3. **Error handling**
   - logs failed retrieval with routing trace
   - re-throws errors after logging

4. **Pipeline step timing**
   - records timing for each pipeline step
   - totalLatencyMs is recorded

### Part 6: updateEntryEmbeddingCache()

Test with mock store:

1. **Success path**
   - updates entry.embeddingCache
   - sets textHash, vector, createdAt, revision

2. **Error path**
   - throws AppError 404 for non-existent entry

## Mock Strategy

The orchestrator has many dependencies. Use selective mocking:

1. **Don't mock**: Pure helper functions in the same file
2. **Mock**: External recall modules (semantic, keyword, graph-assisted)
3. **Mock**: Store and services for searchKnowledge tests
