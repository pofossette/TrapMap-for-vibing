# Plan 70-03: Artifact Pipeline and Postgres Store Tests

**Goal:** Add tests for artifact indexing pipeline and PostgreSQL store operations.

## Scope

Create two test files:
1. `packages/server/src/lib/indexing/artifact-pipeline.test.ts` - Artifact adapter fan-out tests
2. `packages/server/src/lib/persistence/postgres-store.test.ts` - Database store operations tests

## Test File 1: artifact-pipeline.test.ts

### Module Analysis

`artifact-pipeline.ts` is a simple fan-out seam:
- `registerArtifactAdapters()` - Set registered adapters
- `getArtifactAdapters()` - Get registered adapters
- `runArtifactAdapterFanOut()` - Fan-out to all adapters
- `runArtifactAdapterRemoval()` - Call remove on all adapters

### Test Categories

#### Adapter Registration

1. **registerArtifactAdapters() and getArtifactAdapters()**
   - registers adapters array
   - getArtifactAdapters returns registered adapters
   - can be called multiple times (replaces previous)
   - defaults to empty array

#### runArtifactAdapterFanOut()

1. **Success path**
   - calls sync() on each adapter
   - returns success: true when all succeed
   - collects results from each adapter
   - uses registered adapters when not provided

2. **Adapter override**
   - uses adapters parameter when provided
   - does not modify registered adapters

3. **Error handling**
   - returns success: false when any adapter fails
   - catches adapter exceptions
   - records error message in result
   - continues to other adapters after failure

4. **Performed work tracking**
   - records performedWork from each adapter
   - aggregates correctly

#### runArtifactAdapterRemoval()

1. **Removal path**
   - calls remove() on each adapter
   - uses registered adapters when not provided
   - uses adapters parameter when provided

### Test Count Estimate: 12-15 tests

### Mock Strategy

Create mock adapters:

```typescript
const createMockAdapter = (overrides = {}): ArtifactGraphAdapter => ({
  sync: vi.fn().mockResolvedValue({ success: true, performedWork: true, error: null }),
  remove: vi.fn().mockResolvedValue(undefined),
  ...overrides,
});
```

## Test File 2: postgres-store.test.ts

### Module Analysis

`PostgresStore` class:
- `snapshot()` - Get current StoreData from DB
- `transact()` - Mutate StoreData in transaction
- `nextId()` - Generate next ID for prefix
- `close()` - Close pool
- `getPool()` - Get underlying pool

### Test Strategy

PostgresStore requires a real or in-memory PostgreSQL. Options:

1. **Mock the pool** - Simpler but less realistic
2. **Use pg-mem** - In-memory PostgreSQL clone

Recommendation: Use mock pool for unit tests since the store operations are straightforward JSONB operations.

### Test Categories

#### snapshot()

1. **Empty store**
   - returns createEmptyStoreData() when no row exists

2. **With data**
   - returns parsed data from store_snapshot row
   - handles null data field gracefully

#### transact()

1. **Success path**
   - begins transaction
   - locks row with FOR UPDATE
   - calls mutator with data
   - commits on success
   - returns mutator result

2. **Error handling**
   - rolls back on error
   - re-throws error after rollback
   - handles rollback failure gracefully

3. **Upsert behavior**
   - inserts new row if not exists
   - updates existing row with ON CONFLICT

#### nextId()

1. **ID generation**
   - increments counter for prefix
   - returns `${prefix}_${counter}`
   - updates counter in data object

2. **Multiple prefixes**
   - maintains separate counters per prefix

#### close()

- calls pool.end()

#### getPool()

- returns the pool instance

### Mock Strategy

```typescript
const createMockPool = () => ({
  query: vi.fn(),
  connect: vi.fn().mockResolvedValue({
    query: vi.fn(),
    release: vi.fn(),
  }),
  end: vi.fn(),
});
```
