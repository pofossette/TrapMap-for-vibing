<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| local filesystem -> CLI import helper | untrusted file paths and bytes are classified before becoming canonical transport |
| CLI transport -> server import route | the server must distrust client-supplied file roles, levels, and paths |
| artifact persistence -> derivation seam | only derivation-eligible files may become profile/capsule text |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-13-01 | Tampering | CLI/server path handling | mitigate | normalize relative paths, reject absolute or `..` segments, and keep canonical paths in contracts/helpers before persistence |
| T-13-02 | Information Disclosure | derivation and manifest assembly | mitigate | enforce `includeInDerivation` / `activationOnly` boundaries so `assets/` and `scripts/` stay out of profile/capsule text |
| T-13-03 | Elevation of Privilege | `POST /v1/operations/import` | mitigate | retain current `resolveAuthContext()`, `requirePermission()`, requested-level checks, and real-user ownership rules on the route |
| T-13-04 | Repudiation | import transaction | mitigate | emit audit events in the same transaction with artifact id, `sourceKind`, format, and requested level payload details |
</threat_model>
