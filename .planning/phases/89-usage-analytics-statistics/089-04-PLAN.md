2. Add a helper function after the imports (around line 26, before `retrievalRoutes`):
```typescript
import { randomUUID } from 'node:crypto';

/**
 * Build usage events from retrieval result.
 * Creates one event per returned entry (hit).
 */
function buildUsageEvents(
  auth: { actorId: string; activeTeamId: string | null },
  result: { globalConstraints: Array<{ id: string }>; projectKnowledge: Array<{ id: string }> },
  queryId: string,
  queryText?: string,
): UsageEventInput[] {
  const events: UsageEventInput[] = [];

  for (const entry of result.globalConstraints) {
    events.push({
      queryId,
      teamId: auth.activeTeamId,
      accountId: auth.actorId,
      entryType: 'knowledge', // global constraints are knowledge entries
      entryId: entry.id,
      queryText,
    });
  }

  for (const entry of result.projectKnowledge) {
    events.push({
      queryId,
      teamId: auth.activeTeamId,
      accountId: auth.actorId,
      entryType: 'knowledge',
      entryId: entry.id,
      queryText,
    });
  }

  return events;
}
```

```typescript
        buildUsageEvents(auth, result, queryId, query.query),
      );
    }
```

Add this after the `void logUserOperation(...)` block (around line 52) and before the return statement.

## Security Threat Model (ASVS L1)

### STRIDE Analysis for Integration

| Threat | STRIDE Category | Severity | Mitigation |
|--------|-----------------|----------|------------|
| Event injection | Tampering | LOW | Events derived from trusted source (auth context + validated query results) |
| Blocking retrieval pipeline | Denial of Service | LOW | Fire-and-forget pattern with `void` - analytics never blocks response |
| Data leakage via queryText | Information Disclosure | LOW | queryText is user's own search query - not sensitive |

### Standard Controls Applied
1. **Non-blocking writes**: `void repo.recordEvents(...)` pattern - failures don't affect retrieval
2. **Trusted data source**: Events built from validated auth context and query results
3. **Graceful degradation**: `if (usageAnalyticsRepo)` check - works without PostgreSQL

### Code Patterns Used
- `void repo.recordEvents(...)` - fire-and-forget
- `if (usageAnalyticsRepo)` - conditional availability
- `randomUUID()` for query grouping
</threat_model>
