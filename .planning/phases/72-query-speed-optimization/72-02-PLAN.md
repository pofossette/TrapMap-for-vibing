# PLAN 72-02: Optimize semantic recall with batch embedding lookup

## Problem

In `orchestrator.ts`, `semanticRecall()` and `computeSemanticCandidates()` compute embeddings for ALL eligible entries on every query:

```typescript
// orchestrator.ts line 471-496
const scoredEntries = (
  await Promise.all(
    eligibleEntries.map(async (entry) => {
      const entryVector = await semanticGetEntryEmbedding(entry); // Computes embedding
      const similarity = cosineSimilarity(queryVector, entryVector);
      // ...
    }),
  )
).filter((result): result is ScoredEntry => result !== null);
```

This is O(n) embedding computations per query, even when embeddings are cached in the database.

## Solution

Add batch embedding retrieval to `semantic.ts`:

1. **Create `getBatchEmbeddings()` function**:
   - Accept array of entry IDs
   - Return Map<entryId, embedding> for entries with cached embeddings
   - Only compute embeddings for cache misses

2. **Modify `semanticRecall()` path**:
   - First, fetch all cached embeddings in one batch
   - Only compute missing embeddings
   - Use precomputed query embedding

3. **Add embedding cache hit rate tracking**:
   - Track cache hits vs misses
   - Log to RAG log for monitoring

## Implementation

```typescript
// packages/server/src/lib/retrieval/recall/semantic.ts

/**
 * Batch fetch embeddings for multiple entries.
 * Returns cached embeddings for entries with indexState.vector.status === 'synced'.
 * Computes and caches embeddings only for missing entries.
 */
export async function getBatchEmbeddings(
  entries: KnowledgeRecord[],
): Promise<Map<string, { vector: number[]; fromCache: boolean }>>

/**
 * Optimized semantic recall using batch embedding retrieval.
 */
export async function optimizedSemanticRecall(
  queryVector: number[],
  entries: KnowledgeRecord[],
  filters: RetrievalQuery['filters'],
): Promise<ScoredEntry[]>
```

## Performance Improvement

- **Before**: O(n) embedding API calls per query (or O(n) cache checks)
- **After**: 1 batch lookup for all cached embeddings, O(miss_count) computations
