# PLAN 72-04: Add database-level vector similarity search

## Problem

Current semantic retrieval loads all entries into memory and computes cosine similarity in JavaScript:

```typescript
// orchestrator.ts line 468-505
const queryVector = await getQueryEmbedding(seed);
const scoredEntries = (
  await Promise.all(
    eligibleEntries.map(async (entry) => {
      const entryVector = await semanticGetEntryEmbedding(entry);
      const similarity = cosineSimilarity(queryVector, entryVector); // JavaScript computation
      // ...
    }),
  )
).filter(...);
```

This is O(n) memory and computation for n entries, regardless of how many results are needed.

## Solution

Add database-level vector search using pgvector:

1. **Create `db-search.ts`** with:
   - `vectorSimilaritySearch()` - use pgvector's `<=>` operator for cosine distance
   - `SearchFilters` type for team, level, scope constraints
   - Integration with existing `knowledge_embeddings` table

2. **Add HNSW index** to knowledge_embeddings:
   - `CREATE INDEX ON knowledge_embeddings USING hnsw (vector vector_cosine_ops)`
   - Enables approximate nearest neighbor search in O(log n)

3. **Hybrid approach**:
   - Use DB search for candidate retrieval
   - Apply reranking in-memory for final scoring

## Implementation

```typescript
// packages/server/src/lib/retrieval/db-search.ts

export interface VectorSearchOptions {
  /** Query embedding vector */
  queryVector: number[];
  /** Maximum results to return */
  limit: number;
  /** Filter by team ID */
  teamId?: string | null;
  /** Minimum required level */
  minLevel?: number;
  /** Filter by scope */
  scope?: 'global' | 'project';
}

export interface VectorSearchResult {
  entryId: string;
  similarity: number;
  metadata: {
    shortcut: string;
    labels: string[];
    scope: string;
    requiredLevel: number;
  };
}

/**
 * Perform vector similarity search using pgvector.
 * Returns entries ordered by cosine similarity.
 */
export async function vectorSimilaritySearch(
  pool: Pool,
  options: VectorSearchOptions,
): Promise<VectorSearchResult[]>

/**
 * Create HNSW index on knowledge_embeddings if not exists.
 * Should be called during server startup.
 */
export async function ensureVectorIndex(pool: Pool): Promise<void>
```

## SQL for Vector Search

```sql
-- Create HNSW index for cosine similarity
CREATE INDEX IF NOT EXISTS knowledge_embeddings_vector_idx
ON knowledge_embeddings
USING hnsw (vector vector_cosine_ops)
WITH (m = 16, ef_construction = 64);

-- Query for similarity search
SELECT
  entry_id,
  1 - (vector <=> $1::vector) as similarity,
  shortcut,
  labels,
  scope,
  required_level
FROM knowledge_embeddings
WHERE status = 'synced'
  AND ($2::text IS NULL OR team_id = $2)
  AND required_level <= $3
ORDER BY vector <=> $1::vector
LIMIT $4;
```

## Performance Improvement

- **Before**: O(n) in-memory computation, loads all entries
- **After**: O(log n) indexed search, returns only matching entries
