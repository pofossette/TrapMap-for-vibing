# PLAN 72-01: Add retrieval performance benchmarking utilities

## Problem

Current retrieval latency is measured but there's no systematic way to:
1. Establish baseline performance metrics
2. Track performance changes over time
3. Identify slow pipeline steps

The RAG logging captures latencies but requires production traffic to analyze.

## Solution

Add benchmarking utilities for retrieval pipeline performance measurement:

1. **Create `benchmark.ts`** with:
   - `measureRetrievalLatency()` - time full retrieval operations
   - `measurePipelineStep()` - time individual pipeline steps
   - `RetrievalBenchmarkResult` type with latency breakdown
   - `compareBenchmarkResults()` - compare before/after optimization

2. **Benchmark scenarios** for common query patterns:
   - Semantic search with small dataset (< 10 entries)
   - Semantic search with medium dataset (100+ entries)
   - Hybrid search with keyword matches
   - Graph-assisted search with graph expansion

3. **Integration with existing timing**:
   - Reuse `timedStep()` pattern from orchestrator.ts
   - Produce structured results for comparison

## Implementation

```typescript
// packages/server/src/lib/retrieval/benchmark.ts

export interface RetrievalBenchmarkResult {
  timestamp: string;
  scenario: string;
  entryCount: number;
  totalLatencyMs: number;
  steps: {
    parse: number;
    snapshot: number;
    eligibility: number;
    routing: number;
    recall: number;
    assembly: number;
  };
  memoryUsage: {
    heapUsedMB: number;
    heapTotalMB: number;
  };
}

export async function runRetrievalBenchmark(
  entries: KnowledgeRecord[],
  query: string,
  mode: 'semantic' | 'hybrid' | 'graph-assisted',
): Promise<RetrievalBenchmarkResult>

export function compareBenchmarkResults(
  before: RetrievalBenchmarkResult,
  after: RetrievalBenchmarkResult,
): { improvement: number; stepImprovements: Record<string, number> }
```
