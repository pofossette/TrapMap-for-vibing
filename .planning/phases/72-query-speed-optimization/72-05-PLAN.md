# PLAN 72-05: Add database-level keyword search with GIN index

## Problem

Current keyword recall loads all entries and tokenizes them in JavaScript:

```typescript
// keyword.ts line 178-224
export async function keywordRecall(
  queryText: string,
  entries: KnowledgeRecord[],
): Promise<RecallCandidate[]> {
  const queryTokens = normalizeQuery(queryText);
  // ...
  // Pre-tokenize all entries for efficiency (but still in-memory)
  const entryTokenMaps = new Map<string, ReturnType<typeof tokenizeEntry>>();
  for (const entry of entries) {
    entryTokenMaps.set(entry.id, tokenizeEntry(entry));
  }
  // Score each entry...
}
```

This is O(n * m) where n = entries, m = query tokens, and loads all entries into memory.

## Solution

Add database-level keyword search:

1. **Add GIN index** on knowledge_keywords.tokens:
   - `CREATE INDEX USING gin (tokens gin__int_ops)` or use JSONB path ops
   - Enables fast containment queries

2. **Create `keywordSearch()` function**:
   - Query knowledge_keywords table directly
   - Use PostgreSQL array operators (`&&` for overlap)
   - Return pre-computed scores from indexed data

3. **Hybrid approach**:
   - Use DB search for initial candidate retrieval
   - Apply field-weight scoring in-memory for top candidates

## SQL for Keyword Search

```sql
-- Add GIN index for array containment queries
CREATE INDEX IF NOT EXISTS knowledge_keywords_tokens_idx
ON knowledge_keywords
USING gin (tokens jsonb_path_ops);

-- Query for token overlap
SELECT
  entry_id,
  tokens,
  field_tokens
FROM knowledge_keywords
WHERE status = 'synced'
  AND tokens ?| $1::text[]  -- tokens array overlaps query tokens
  AND ($2::text IS NULL OR team_id = $2)
  AND required_level <= $3;
```

## Performance Improvement

- **Before**: O(n * m) in-memory tokenization and matching
- **After**: O(log n) indexed search, returns only matching entries
