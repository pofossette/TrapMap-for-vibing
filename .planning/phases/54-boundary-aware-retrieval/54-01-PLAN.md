    **Step 3: Create boundary match module** as NEW file `packages/server/src/lib/retrieval/boundary-match.ts`:

    This module provides three pure functions: filter, score, explain.

    ```typescript
    import type { Boundary, BoundaryContext, BoundaryExplanation, VersionConstraint } from '@trapmap/contracts';
    import { normalizeContextLabel, normalizePackageName } from '../indexing/boundary-normalize.js';

    /** Penalty for excluded context match (BOUND-04) */
    export const BOUNDARY_EXCLUDED_PENALTY = -0.15;
    /** Boost for preferred context match (BOUND-04) */
    export const BOUNDARY_PREFERRED_BOOST = 0.10;
    ```

    **filterByBoundary(entries, boundaryContext)**: Returns entries whose required constraints are satisfied.
    - If boundaryContext is undefined/null/empty, return all entries (no filtering).
    - For each entry with `entry.boundary`:
      - If `entry.boundary.versions` has constraints with `required: true` prerequisites, or the version constraints themselves:
        - For each `VersionConstraint` in `entry.boundary.versions`:
          - Check if `boundaryContext.versions` contains the same package name (normalize both sides with `normalizePackageName`).
          - If the package exists in query versions but the version does NOT satisfy the constraint range, EXCLUDE the entry.
          - For simple range checking: implement `satisfiesRange(queryVersion: string, constraintRange: string): boolean` that handles common semver patterns: `>=X.Y.Z`, `^X.Y.Z`, `~X.Y.Z`, `>X.Y.Z`, `<=X.Y.Z`, `<X.Y.Z`, `X.Y.Z` (exact). Use a simple semver comparison: split on `.`, compare major/minor/patch numerically. For ranges starting with `>=`, check if query version >= constraint version. For `^`, check same major. For `~`, check same major.minor. For exact, check equality.
      - If entry has `prerequisites` with `required: true`, those are informational only (no structured version to check against) -- skip them for hard filtering.
    - If entry has no boundary, it passes filtering (no constraints to violate).
    - Return the filtered list.

    **computeBoundaryScoreDelta(entry, boundaryContext)**: Returns a number to add to the score.
    - If boundaryContext is undefined/null/empty, return 0.
    - If entry.boundary is null, return 0.
    - Start with delta = 0.
    - For excluded context match:
      - Normalize each `boundaryContext.contexts` label and each `entry.boundary.exclusions` where `kind === 'context'`.
      - For each query context label, if it appears in any exclusion description (case-insensitive), apply `BOUNDARY_EXCLUDED_PENALTY` (-0.15).
      - For platform exclusions: if `boundaryContext.platform` is set, check `entry.boundary.exclusions` where `kind === 'platform'`. If the normalized query platform appears in the exclusion description, apply penalty.
    - For preferred context match:
      - Normalize each `boundaryContext.contexts` label and each `entry.boundary.context` label.
      - For each match (normalized equality), apply `BOUNDARY_PREFERRED_BOOST` (+0.10).
    - Return delta.

    **buildBoundaryExplanation(entry, boundaryContext, scoreDelta)**: Returns `BoundaryExplanation`.
    - If boundaryContext is undefined/null/empty: return `{ checked: false, requiredSatisfied: true, warnings: [], boosts: [] }`.
    - If entry.boundary is null: return `{ checked: true, requiredSatisfied: true, warnings: [], boosts: [] }`.
    - Build `warnings` array: for each exclusion match, add `"Excluded {kind}: {description}"`.
    - Build `boosts` array: for each context match, add `"Applicable context: {label}"`.
    - Compute `requiredSatisfied`: true if no version constraint violations, false otherwise.
    - Return `{ checked: true, requiredSatisfied, warnings, boosts }`.

    All three functions must be pure (no side effects, no I/O) and exported.
