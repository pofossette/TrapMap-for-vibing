# TrapMap Knowledge Workflow

## Control Path

1. Resolve the CLI invocation first: prefer `trapmap`; in this monorepo use `pnpm --filter @trapmap/cli dev -- <command>` when the built binary is unavailable.
2. **Before planning and implementation, load knowledge context with a single command:**
   ```bash
   trapmap load "<task or domain seed>"
   ```
   This retrieves and formats traps, skills, and capsules into an agent-consumable markdown context block. The output includes:
   - Blocking traps (constraints to respect)
   - Recommended skills (guidance to apply)
   - Routing metadata (confidence, recall channels)

   Use `--scope project` for project-specific knowledge, `--label <label>` to filter by domain, and `--skill-budget <n>` to limit recommendations.
3. Read the markdown context block and treat traps as constraints before applying skill guidance. If the output includes `[HARD]` traps, they must be mitigated in your plan.
4. If the task scope changes materially, rerun `trapmap load` with a seed that matches the new scope.
5. If TrapMap retrieval is blocked by auth, server, or install state, record the exact blocker. Do not claim there were no relevant traps or skills.
6. After a solved issue, preserve reusable experience only when it is compact, verified, and non-secret. Use [references/accumulation.md](references/accumulation.md).

## Primary: trapmap load (Recommended)

Use `trapmap load` as the primary entry point for knowledge retrieval. It encapsulates skill search, trap search, and plan compilation into a single command outputting agent-consumable markdown.

### Basic Usage

```bash
trapmap load "<task seed>"
```

### Options

| Option | Description | Default |
|--------|-------------|---------|
| `--scope <scope>` | Filter by scope (global or project) | all scopes |
| `--label <label>` | Filter by label (repeatable) | no filter |
| `--max-results <n>` | Max capsules/entries in fallback | 10 |
| `--skill-budget <n>` | Max skills in plan | 3 |
| `--max-depth <n>` | Max graph expansion depth | 2 |
| `--fallback <mode>` | Fallback mode: auto, v2-capsule, v1-graph-assisted | auto |
| `--stdin` | Read seed from stdin | false |
| `--json` | Output raw JSON instead of markdown | false |

### Output Format

The command outputs a markdown context block:

```markdown
<!-- trapmap-load-context -->
## TrapMap Context

### Blocking Traps
1. **[HARD] Avoid global state** (scope: project, score: 0.90)
   > Global state causes race conditions in tests
   - Source: `entry-123`

### Recommended Skills
1. **Use dependency injection** (score: 0.85)
   - Situation: Testing components in isolation
   - Problem: Hard to mock dependencies
   - Goal: Inject dependencies for testability
   - References: `ref/guide.md`
   - Source: `artifact-456`

### Routing
- Mode: graph-assisted
- Confidence: 0.90 (high)
- Channels: semantic, keyword

<!-- /trapmap-load-context -->
```

### When to Use Each Flag

**`--scope project`**: Use when the task is specific to the current project (not global engineering patterns).

**`--label backend`, `--label api`**: Use to filter knowledge to specific domains. Repeatable.

**`--skill-budget 5`**: Increase when you need more skill recommendations (max: 10).

**`--json`**: Use when parsing output programmatically or passing to other tools.

**`--stdin`**: Use when piping context from another command:
```bash
echo "how to handle database deadlocks" | trapmap load --stdin
```

## Alternative: Manual Search Commands

For fine-grained control, use individual commands:

### Skill Before Plan (Manual)

Run this before forming a plan:

```bash
trapmap skill search-by-content "<task or domain seed>" --max-results 5 --json
```

Select the top 1-3 matches that are directly applicable. Put weaker matches in citations or ignore them.

### Trap Before Implementation (Manual)

Run this after planning and before code changes:

```bash
trapmap search "<planned implementation area or risk seed>" --scope project --mode graph-assisted --max-results 5 --json
```

Useful `search` flags include `--label`, `--scope`, `--mode semantic|hybrid|graph-assisted`, `--v2`, `--summary`, `--stdin`, and `--no-refinement`.

## Trap-First Selection

Compile results in this order:

1. Blocking traps and hard constraints.
2. Skills/capsules that directly mitigate those traps.
3. Verification commands or observable confirmations.
4. Extra matches as citations only.

If a trap conflicts with a skill, the trap wins until the plan explicitly mitigates it.

If a command or flag is uncertain, run:

```bash
trapmap --help
trapmap <command> --help
```
