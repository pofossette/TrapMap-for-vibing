# Plan 06: CLI Option Cleanup, Input Validation, and Doc Sync

## Objective
Remove the dead `--max-results` CLI option, add NaN guards on integer parsing, and sync skill documentation — closing review findings WR-01, WR-03, and IN-02.

## Context
The code review found that `--max-results` is declared on `load.ts:24` but never sent to the API because `graphPlanSearchQuerySchema` does not include a `maxResults` field. The `planQuerySchema` (which `graphPlanSearchQuerySchema` extends) only accepts `seed`, `skillBudget`, and `maxDepth`. Users passing `--max-results` get no effect. Additionally, `parseInt` on lines 73-74 has no NaN guard, meaning invalid input like `--skill-budget abc` produces `NaN` which serializes to `null` in JSON. The skill docs at `retrieval.md:67` list `--max-results` as a load flag, perpetuating the confusion.
