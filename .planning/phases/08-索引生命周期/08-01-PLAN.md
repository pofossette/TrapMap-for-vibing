<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| knowledge snapshot -> normalization | approved lifecycle data becomes canonical index input |
| normalization -> adapter fan-out | all adapters must consume the same document so no channel invents its own visibility rules |
| pipeline -> JSON store | sync metadata writes must not corrupt existing knowledge lifecycle records |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-08-01 | Tampering | `normalize.ts` / `pipeline.ts` | mitigate | use one `NormalizedIndexDocument` with deterministic `contentHash`, test idempotency, and persist sync metadata only under `indexState` |
| T-08-02 | Information Disclosure | `pipeline.ts` | mitigate | make desired index presence depend on `lifecycleState === 'approved'` only, never on adapter-local auth checks |
| T-08-03 | Denial of Service | `pipeline.ts` reconcile path | mitigate | keep reconciliation bounded to store entries, reuse normalized docs per entry, and cover unchanged-entry no-op behavior in tests |
| T-08-04 | Repudiation | `store.ts` sync metadata | mitigate | persist `lastSyncedAt` and `lastError` fields so drift and failures remain inspectable in the authoritative store |
</threat_model>
