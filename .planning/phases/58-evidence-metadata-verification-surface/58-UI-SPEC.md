## CLI Output Contracts

### Evidence Metadata Display Format

Evidence metadata appears in CLI output following the existing `formatEntry` pattern from `knowledge.ts`:

```
Evidence:
  Source: <sourceType>: <sourceRef>
  Level: <evidenceLevel>
  Verified: <verifiedAt> by <verifiedBy>
```

**Field formatting rules:**

| Field | Format | Example |
|-------|--------|---------|
| `sourceType` | lowercase, dash-separated | `incident-report`, `runbook`, `official-docs` |
| `sourceRef` | URL or identifier, truncated to 60 chars | `https://docs.example.com/...` or `INC-12345` |
| `evidenceLevel` | enum label with visual indicator | `strong`, `moderate`, `weak`, `unverified` |
| `verifiedAt` | ISO date (YYYY-MM-DD) | `2026-04-15` |
| `verifiedBy` | actor handle | `@alice` |

### Compact Retrieval Response Format

In retrieval responses, evidence metadata uses a compact single-line format:

```
Evidence: <level> | <sourceType> | <verifiedAt>
```

**Example:**
```
Evidence: strong | incident-report | 2026-04-15
```

When `evidenceLevel` is `unverified`, display:
```
Evidence: unverified
```

### Empty State

When no evidence metadata exists:
```
Evidence: not recorded
```

## CLI Input Contracts

### Review Command Extensions

The `review:approve` command accepts optional evidence flags:

```bash
review:approve <entryId> --notes <text> \
  [--evidence-type <type>] \
  [--evidence-ref <ref>] \
  [--evidence-level <level>]
```

**Flag specifications:**

| Flag | Type | Required | Description |
|------|------|----------|-------------|
| `--evidence-type` | enum | optional | One of: `incident-report`, `runbook`, `official-docs`, `community-post`, `personal-experience`, `ai-inference` |
| `--evidence-ref` | string | optional | URL or identifier referencing the source (max 280 chars) |
| `--evidence-level` | enum | optional | One of: `strong`, `moderate`, `weak`, `unverified` (default: `unverified`) |

**Validation rules:**
- If `--evidence-ref` provided, `--evidence-type` becomes required
- If `--evidence-level` is `strong` or `moderate`, `--evidence-ref` becomes required
- `verifiedAt` and `verifiedBy` are set automatically from session context

### Evidence Update Command

New command for updating evidence on existing entries:

```bash
evidence:update <entryId> \
  --type <type> \
  --ref <ref> \
  --level <level>
```

This updates evidence metadata and sets `verifiedAt` to current timestamp, `verifiedBy` to current user.

## Schema Contracts

### Evidence Metadata Schema

Following the pattern from `decay.ts`, evidence metadata is a schema extension:

```typescript
export const evidenceSourceSchema = z.enum([
  'incident-report',
  'runbook',
  'official-docs',
  'community-post',
  'personal-experience',
  'ai-inference',
]);

export const evidenceLevelSchema = z.enum([
  'strong',      // Primary source, verified by multiple parties
  'moderate',    // Secondary source or single verification
  'weak',        // Indirect source or unverified claim
  'unverified',  // No external validation (default)
]);

export const evidenceMetaSchema = z.object({
  sourceType: evidenceSourceSchema.nullable().default(null),
  sourceRef: z.string().max(280).nullable().default(null),
  evidenceLevel: evidenceLevelSchema.default('unverified'),
  verifiedAt: isoTimestampSchema.nullable().default(null),
  verifiedBy: actorRefSchema.nullable().default(null),
});
```

### Integration Points

| Location | Integration |

| `skillArtifactSchema` | Extend with `evidence: evidenceMetaSchema` |

## API Response Contracts

### Retrieval Response Extension

Additive field in retrieval responses (backward-compatible):

```json
{
  "entryId": "abc123",
  "shortcut": "...",
  "evidence": {
    "sourceType": "incident-report",
    "sourceRef": "https://...",
    "evidenceLevel": "strong",
    "verifiedAt": "2026-04-15T00:00:00Z",
    "verifiedBy": {
      "id": "user-123",
      "handle": "@alice"
    }
  }
}
```

**Compact form for list views:**
```json
{
  "evidence": {
    "level": "strong",
    "sourceType": "incident-report",
    "verifiedAt": "2026-04-15"
  }
}
```

### Admin List Response

New query parameters for admin list endpoints:

```
GET /v1/knowledge?evidenceLevel=weak&missingEvidence=true
```

| Parameter | Type | Description |
|-----------|------|-------------|
| `evidenceLevel` | enum | Filter by evidence level |
| `missingEvidence` | boolean | Filter entries without evidence metadata |
| `sourceType` | enum | Filter by source type |
| `verifiedBefore` | ISO date | Filter entries verified before date |

## Color

Terminal color codes for evidence level indicators:

| Level | ANSI Code | Usage |
|-------|-----------|-------|
| `strong` | `\x1b[32m` (green) | High-confidence evidence |
| `moderate` | `\x1b[33m` (yellow) | Medium-confidence evidence |
| `weak` | `\x1b[35m` (magenta) | Low-confidence evidence |
| `unverified` | `\x1b[90m` (dim gray) | No external validation |

**Note:** Colors only applied when terminal supports color (check `process.env.NO_COLOR` and `process.stdout.isTTY`).
