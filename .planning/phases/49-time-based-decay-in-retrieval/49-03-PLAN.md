# Phase 49-03: Rerank Freshness Integration

## Summary

Integrate freshness decay multiplier into the retrieval rerank pipeline. Apply freshness multiplier as a multiplicative factor after all additive boosts/penalties, preserving relative ranking differences.

## Context

The rerank pipeline currently applies:
1. Base score from merge stage
2. Both-channel boost (+0.15)
3. Token density boost (+0.10)
4. Stale decay penalty (-0.10)
5. Cap at [0, 1]

This plan adds freshness multiplier as step 4.5, applied after stale penalty but before capping. The multiplier is multiplicative rather than additive to preserve relative ranking differences.

**Key integration point:** `rerankCandidates()` function in `rerank.ts`

```typescript
// Apply soft decay penalty for stale entries
if (staleDecayPenalty > 0 && hasStaleDecayState(candidate)) {
  finalScore -= staleDecayPenalty;
}

// Apply freshness decay multiplier (Phase 49: DECAY-02)
// Multiplicative to preserve relative ranking differences
const freshnessMultiplier = computeFreshnessMultiplier(
  candidate.entry,
  freshnessConfig,
);
if (freshnessMultiplier < 1.0) {
  finalScore *= freshnessMultiplier;
}

// Cap at 1.0 to maintain score bounds
finalScore = Math.min(1, Math.max(0, finalScore));
```
