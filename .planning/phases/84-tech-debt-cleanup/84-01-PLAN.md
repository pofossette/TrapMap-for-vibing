### Task 2: Fix duplicate export in boundary.ts

<read_first>
- packages/contracts/src/domain/boundary.ts (current state with duplicate export)
- packages/contracts/src/domain/artifacts.ts (imports boundaryMetaSchema - MUST CHECK)
</read_first>

<action>
The knip warning shows `boundarySchema|boundaryMetaSchema` as duplicate exports because line 195 has:
```typescript
export const boundaryMetaSchema = boundarySchema;
```

This is an intentional alias for semantic clarity (boundaryMetaSchema for artifacts, boundarySchema for queries).
The duplicate export warning is expected behavior - both names export the same schema object.

Fix by changing the alias to a re-export type declaration instead:

```typescript
// Before (line 195):
export const boundaryMetaSchema = boundarySchema;

// After:
export type BoundaryMeta = Boundary;
export { boundarySchema as boundaryMetaSchema };
```

This preserves backward compatibility (artifacts.ts still imports `boundaryMetaSchema`) while making the intent explicit.
</action>

<acceptance_criteria>
- File `packages/contracts/src/domain/boundary.ts` contains `export type BoundaryMeta = Boundary;`
- File contains `export { boundarySchema as boundaryMetaSchema };`
- `npx tsc --noEmit` passes in packages/contracts
- `packages/contracts/src/domain/artifacts.ts` still compiles (imports boundaryMetaSchema)
</acceptance_criteria>
