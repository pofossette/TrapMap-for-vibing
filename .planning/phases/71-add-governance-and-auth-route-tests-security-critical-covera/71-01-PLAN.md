# Plan 71-01: CLI HTTP Client Tests

## Objective

Create unit tests for the HTTP client module used by all CLI commands.

## Scope

**File to create:** `packages/cli/src/lib/http.test.ts`

**Exports to test:**
- `ApiError` class (constructor, properties)
- `apiRequest<T>()` function (GET, POST, PATCH, error handling)
- `requireSessionToken()` function

## Test Cases

### ApiError class (3 tests)

1. **constructor sets properties**
   - statusCode, payload, message are accessible
   - inherits from Error

2. **instanceof Error check**
   - ApiError instances are also Error instances

3. **message is set correctly**
   - Custom message passed to constructor

### apiRequest function (18 tests)

**URL construction:**
4. Uses state.serverUrl when options.serverUrl not provided
5. Uses options.serverUrl when provided (override)
6. Constructs correct path with query params

**HTTP method handling:**
7. Defaults to GET when method not specified
8. Uses POST method when specified
9. Uses PATCH method when specified

**Header handling:**
10. Sets content-type for requests with body
11. Omits content-type for requests without body
12. Sets authorization header from state.sessionToken
13. Sets authorization header from options.sessionToken (override)
14. Omits authorization when no token available

**Response handling:**
15. Parses JSON response body
16. Returns sessionToken from x-session-token header
17. Handles empty response body (null payload)

**Error handling:**
18. Throws ApiError for non-OK responses
19. Extracts message from error payload
20. Falls back to status code message when no payload message

### requireSessionToken function (3 tests)

21. Returns token when sessionToken exists
22. Throws Error when sessionToken is null
23. Error message mentions 'login' command

## Implementation Notes

- Mock `fetch` globally using `vi.stubGlobal`
- Create mock responses with various status codes
- Test both success and error paths
- Use `CliState` interface from config.ts for typing
